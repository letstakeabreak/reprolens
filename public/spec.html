3. REST API Interface Specification

Express Backend
Method & Path Description Input Parameters Output Format
POST /api/extract-frames Extracts keyframes at 2fps from an uploaded or preloaded bug recording. multipart/form-data with video (optional, defaults to sample) { success: true, totalFrames: 15, frames: [...] }
POST /api/synthesize Parses extracted frames, infers user action sequence, and synthesizes Playwright test script. None (reads current extracted frames) { success: true, analysis: {...}, code: "..." }
POST /api/run-reproduce Spawns headless Chromium, executes the synthesized sequence, asserts Error 409, and captures evidence screenshot. { detectedActions: [...] } { success: true, status: "REPRODUCED", durationMs: 3209, logs: [...], screenshotUrl: "..." }
GET /api/sample-video Provides metadata and streaming URL for the default 7.3s checkout conflict recording. None { exists: true, url: "/sample_videos/sample_bug.mp4", duration: "7.3s" }
GET /checkout Serves the mock e-commerce checkout web application with the built-in Error 409 conflict bug. None HTML5 Web Application

4. Product Requirements Document (PRD) One-Sheet

c0mpiled-17 Spec
Problem Statement
Software engineers spend 20.4% of every sprint manually guessing and reproducing bug reports submitted as vague screen recordings. 42% of front-end bugs are delayed or closed as "Cannot Reproduce" due to missing interaction context.
Target Personas
1. Frontend Lead Engineer: Needs instant Playwright test scripts from QA Slack clips without manual typing.
2. Solo Technical Founder: Lacks QA resources; needs automated regression assets from real user bug videos.
Success Metrics for 90-Second Hackathon Demo
- Analysis Speed: Extract frames & synthesize test spec in < 5 seconds.
- Execution Reliability: Headless browser reproduces the exact visual 409 error in < 4 seconds.
- Code Quality: Synthesized Playwright code is 100% self-contained with semantic locators and fallback chains.
